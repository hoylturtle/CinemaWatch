Draft; no application submitted. Audited2026-10-21, immutable main snapshot `208da9b98e884c831f25ece0221515a84b9d9654`.

## Defensible positioning

An early-stage, public Android project adapting a pinned Fieldwatch foundation to authorized cinema asset inspection and maintenance, with a deliberately bounded BLE region experiment. Do not describe it as fully licensed original MIT software, a large community project, a production surveying system, a proven customer analytics platform or an AI-powered runtime.

## Readiness gaps to resolve before presenting this as a mature OSS project

1. Clarify original-work licensing and third-party database distribution rights; preserve notices.
2. Publish and verify a non-debuggable release variant with signature continuity.
3. Complete deletion of attachments/caches and document data retention.
4. Reconcile outdated architecture/prototype claims and open-issue acceptance.
5. Provide contribution/security guidance, build checksums/pinned inputs and coverage evidence.
6. Gather authorized physical-device and field benchmarks; disclose unknown states and failures.

These are audit recommendations, not claims that the official program imposes every listed gate. The official page supports maintainer applications and invites projects to explain their ecosystem role even when atypical; it does not provide grounds here to promise selection. See [OpenAI program](https://developers.openai.com/community/codex-for-oss).

## Audit limitations

This audit retrieved current files, all advertised-ref reachable history, releases, selected current CI artifacts and the latest APK. It did not access private operational data, secrets, unreachable/deleted Git objects, conduct credential probing, run a new Android build or physically test RF/ranging. Shared Codex Security preflight resources were unavailable; no formal Standard scan or security certification is claimed. No application, repository write, license change or new release occurred.
